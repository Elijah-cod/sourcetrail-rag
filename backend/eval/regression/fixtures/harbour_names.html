HT-NAMES: Reserved Names for Harbour Telemetry

Published 2026-05-04 by the Harbour Telemetry Working Group.

1. Requirements language

The key words "MUST", "MUST NOT", "REQUIRED", "SHOULD", "SHOULD NOT" and "MAY" in this profile are to be interpreted as described in RFC 2119.

2. Purpose

Telemetry devices on a harbour network need device names that can never collide with real names. This profile reserves two name suffixes, .quayside and .sample, and says how software treats each one.

3. The .quayside suffix

Names ending in .quayside always refer to a device on the local harbour segment.

Applications SHOULD recognise .quayside names and SHOULD resolve them to the local segment without asking a public name server. Name resolution libraries MUST NOT forward .quayside queries to the public DNS. Gateways MAY cache .quayside answers for up to 60 seconds.

4. The .sample suffix

Names ending in .sample are for documentation and examples only.

Authors MAY use .sample names freely in manuals. Applications SHOULD NOT treat .sample names specially. Name servers SHOULD NOT answer queries for .sample names with real addresses.

5. Logging

Devices MUST log every name lookup that fails. Logs SHOULD be kept for 30 days.

6. Security considerations

Because .quayside names are local, an attacker on the segment can impersonate a device. Operators SHOULD use authenticated telemetry where possible.

7. Registry

The working group keeps the list of reserved suffixes. New suffixes REQUIRE a published profile.
